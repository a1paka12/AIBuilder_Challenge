# 보증금 지킴이 개인정보·법적 설계

작성일: 2026-10-03 · 관련 문서: [PRD](PRD.md) · [ARCHITECTURE](ARCHITECTURE.md) · [REFERENCES](REFERENCES.md)

> **한계:** 이 문서는 팀이 조사한 내용을 바탕으로 한 설계 원칙이며 **법률 자문이 아니다.** 실제 출시(유료화 포함) 전에는 변호사의 법률 검토가 필요하다.

---

## 1. 개인정보 처리 설계

### 1-1. 원칙

1. **받지 않을 수 있으면 받지 않는다.** 이번 MVP는 공제 메시지 **텍스트만** 서버를 거친다.
2. **사진은 브라우저 밖으로 내보내지 않는다.** 서버에는 사진 파일의 SHA-256 지문만 보낸다.
3. **본문을 저장·로그하지 않는다.** 서버 로그에는 항목 수·처리 시간만 남긴다.
4. 로그인·회원가입이 없고, 새로고침하면 브라우저 메모리의 데이터가 사라진다.

### 1-2. 처리 항목 (현재 MVP)

| 항목 | 목적 | 어디를 거치나 | 보유 |
|---|---|---|---|
| 공제 메시지 텍스트 | 항목·청구액·원문 인용 정리 | 브라우저 → 서버(경유) → OpenAI API | 서버 **저장 안 함**. 응답 후 메모리에서 사라짐 |
| AI 정리 결과(항목·금액·인용) | 표 표시 | 서버 → 브라우저 | 브라우저 메모리(새로고침 시 삭제) |
| 특약 문구 | 특약 키워드 확인("특약 있음 · 상담 필요") | 브라우저 안에서만 | 브라우저 메모리 |
| 내 이름·장소 | 문의 문자·내용증명 빈칸 채우기 | 브라우저 안에서만 | 브라우저 메모리 |
| 방 사진 | 기록북 미리보기·PDF | 브라우저 안에서만(object URL) | 브라우저 메모리 |
| 사진 지문(SHA-256)·서버 수신 시각·서명 | "이 시각에 이 파일이 있었다" 기록 | 브라우저 → 서버 | `server/data/receipts.jsonl`에 추가 저장 |
| 접속 IP | 속도 제한(분당 30회) | 서버 메모리 | 파일에 기록하지 않음, 서버 재시작 시 사라짐 |

- 지문은 사진 내용을 알 수 없는 64자 문자열이다. 지문 기록에는 이름·연락처·파일명·구역·메모가 들어가지 않는다.
- 현재 지문 기록의 보관 기간은 정해 두지 않았다(추가 전용 파일). 출시 전에 보관 기간과 삭제 요청 절차를 정한다.

### 1-3. 국외 이전 (개인정보 보호법 제28조의8)

| 받는 곳 | 나라 | 전달 항목 | 목적 | 비고 |
|---|---|---|---|---|
| OpenAI (API) | 미국 | 공제 메시지 텍스트 | 항목·금액·인용 추출 | 처리방침 화면에 고지. 제공사의 API 데이터 보관·학습 미사용 정책은 출시 전 다시 확인 |
| Oracle Cloud (서버 호스팅) | 일본(도쿄 리전) | 공제 메시지(경유, 저장 안 함), 사진 지문 기록(저장) | 서비스 운영 | 국내 리전 이전 또는 처리방침 고지 검토 |

### 1-4. 안전조치 (현재 구현)

| 조치 | 내용 |
|---|---|
| 전송 구간 암호화 | Caddy HTTPS(ZeroSSL 인증서) |
| 내부 포트 비공개 | Express는 `127.0.0.1:8420`에만 바인딩 |
| 비밀값 분리 | OpenAI 키·서명 키는 서버 `.env`에만, 배포 rsync에서 `.env` 제외 |
| 본문 비저장·비로그 | `/api/extract`는 본문을 파일·로그에 남기지 않음 |
| AI 응답 개인정보 가림 | 항목명·인용의 주민등록번호·전화번호·계좌번호·이메일 패턴을 `●●●`로 |
| 입력 안내 | 붙여 넣기 전에 이름·전화번호·계좌번호를 지우라고 안내 |
| 남용 방지 | IP당 분당 30회, 본문 3,000자·요청 32KB 제한 |
| 기록 위변조 확인 | 지문 기록마다 HMAC-SHA256 서명 |

**현재의 한계:** 서버는 입력 본문을 가리지 않은 채 OpenAI로 보낸다(가림은 AI 응답에만 적용). 사용자가 개인정보를 지우지 않고 붙여 넣으면 그대로 AI 제공사로 전달될 수 있다.

### 1-5. 향후(창업 목표) 설계

| 기능 | 설계 |
|---|---|
| 입력 본문 가림 | OpenAI로 보내기 전에 서버에서 입력에도 같은 개인정보 패턴 가림 적용, 브라우저에서도 미리 가려 보여 주기 |
| 공제 내역 **사진** 입력 | 브라우저에서 글자 영역만 남기고 이름·연락처·계좌 부분을 가린 뒤, 가린 이미지만 서버로 |
| 계약서 특약 사진 입력 | 브라우저에서 **특약 부분만 자르기 → 가림 → 위치정보(EXIF GPS) 제거** 후 가린 이미지만 서버로 |
| 기록북 보관(유료) | 사용자가 고른 경우에만 위치정보를 지운 사진 업로드, 이사 건 종료 후 보관 기간 지나면 파기 |
| 계정 | 소셜 로그인, 상세 주소·집주인 실명·주민등록번호 받지 않음([ERD.md](ERD.md) 2-2) |

## 2. 법적 설계 원칙

보증금 지킴이는 **공개 자료를 정리해 보여 주는 정보 제공 도구**다. AI는 정리만 하고 판단하지 않는다. 판단과 발송은 사용자가 한다.

### 2-1. 위험과 대응

| 위험 | 근거 | 설계 대응 |
|---|---|---|
| 비변호사의 법률사무 취급 | **변호사법 제109조**: 변호사가 아니면서 금품·이익을 받거나 약속하고 법률 사건에 관해 감정·대리·문서 작성 등 법률사무를 취급하는 행위 금지 | 공제의 적정성·돌려받을 금액·승소 가능성을 판단하지 않는다. 성공보수·해결 수수료를 받지 않는다. 판단·분석 결과를 팔지 않는다. 유료 상품은 방 사진 정리(기록북)와 빈칸 서식뿐 |
| 변호사 소개·알선 대가 | **변호사법 제34조**: 법률 사건을 특정 변호사에게 소개·알선·유인하고 대가를 받는 행위 금지 | 변호사 소개비 없음. 변호사 추천·순위 없음. 대한변협 공식 변호사 검색 링크와 무료 공공 기관만 안내. 사건 정보를 다른 곳에 보내지 않는다 |
| 자동 문서 작성의 법률사무 해당 여부 | **로폼 사건**: 서울행정법원 2023구합60018 → 대법원 2025두35483 심리불속행 기각(2026-02-12). 이용자 입력이 그대로 반영되는 빈칸형 자동작성은 법률사무가 아니라는 취지. 생성형 AI가 문서를 작성하는 방식은 위반 소지가 언급됨 | 문의 문자·내용증명은 **고정 서식 + 사용자가 확인한 항목·금액만** 채운다. 이 단계에 **AI를 쓰지 않는다.** AI는 메시지에서 항목을 옮겨 적는 데만 쓴다 |
| 주민등록번호 처리 | **개인정보 보호법 제24조의2**: 법령 근거 없는 주민등록번호 처리 제한 | 어떤 입력란에도 주민등록번호를 받지 않는다. AI 응답에 섞이면 가림 |
| 개인정보 국외 이전 | **개인정보 보호법 제28조의8** | OpenAI(미국) 전송을 처리방침에 고지(1-3) |
| 생성형 AI 사용 고지 | **AI 기본법 제31조**(투명성: 생성형 AI 사용 사전 고지) | 첫 화면 고지 "공제 내역 정리에 생성형 AI를 사용합니다.", AI가 만든 결과에 "AI" 배지 |
| 공갈 위험 | **형법 제350조**(공갈), **대법원 94도2422**(권리 행사라도 사회통념상 허용 범위를 넘는 해악 고지는 공갈이 될 수 있다는 취지) | 문의 문자는 근거를 묻는 문장만. 내용증명에 보증금과 관계없는 압박 문구(신고·폭로·인터넷 게시 등)를 넣으면 "보증금과 관계없는 압박 문구는 넣을 수 없어요."로 차단 |
| 과장·오인 표시 | 결과를 보장하는 듯한 문구는 이용자를 오인하게 할 수 있음 | 화면에 결론·과장 문구를 쓰지 않는다(2-2). 결제는 연결하지 않았다고 그대로 표시하고 결제 성공 화면을 흉내 내지 않는다 |

### 2-2. 화면 문구 원칙

- **쓰지 않는 표현:** 공제가 부당하다는 결론, 판정, "돌려받을 수 있어요", "안 내도 됩니다", "기준과 다른", "AI 변호사", "법적 효력 보장", "승소" 등 결론·보장·과장 문구.
- **쓰는 표현:** "확인 필요", "특약 있음 · 상담 필요", "특약 확인 안 함", 참고 자료의 **범위 태그**("표준계약서 사용 시", "세입자에게 불리할 수 있음" 등), 출처 링크·확인일.
- 세입자에게 불리할 수 있는 판결(91다22605)도 함께 보여 줘 한쪽 자료만 고르지 않는다.
- 상시 고지: "보증금 지킴이는 공개 자료를 찾아 보여 주는 정보 제공 도구이며, 법률 판단이나 대리를 하지 않습니다."

### 2-3. 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 공제 적정성·돌려받을 금액·승소 가능성 판단, 감가 계산 | 법률 판단(변호사법 제109조) |
| 성공보수·해결 수수료 | 이익을 받는 법률사무 취급 위험(제109조) |
| 변호사 소개비·추천 순위·상담 예약 대행·사건 자료 전달 | 소개·알선 대가 위험(제34조) |
| 문자·카톡 자동 발송, 내용증명 대리 발송 | 대리 행위 위험, 사용자가 직접 보낸다 |
| AI가 문의 문자·내용증명 문장 작성 | 로폼 사건에서 언급된 생성형 AI 문서 작성 위험 |

## 3. 출시 전 점검 목록

- [ ] 변호사 법률 검토(유료 상품 구조, 내용증명 서식, 화면 문구)
- [ ] 개인정보 처리방침 확정: 보호책임자 지정, 지문 기록 보관 기간·삭제 절차
- [ ] 서버 리전(국내 이전 여부)과 국외 이전 고지 범위 확정
- [ ] 입력 본문 개인정보 가림 적용
- [ ] AI 제공사의 데이터 보관·학습 미사용 조건 재확인
- [ ] 결제 연결 시 전자상거래법상 표시·환불 규정 반영
