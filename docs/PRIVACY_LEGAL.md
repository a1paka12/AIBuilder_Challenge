## 1. 개인정보 처리 설계

### 1-1. 원칙

1. **받지 않을 수 있으면 받지 않는다.** 서버를 거치는 사용자 글은 공제 메시지의 **처리본(개인정보를 치환한 글)** 하나뿐이다.
2. **먼저 기기에서 지우고, 사용자가 확인한 것만 보낸다.** 텍스트는 브라우저에서 치환하고 "전송본 확인"을 거쳐야 전송된다. 서버는 한 번 더 가린다(2차 방어).
3. **사진은 브라우저 밖으로 내보내지 않는다.** 가린 처리본을 브라우저에서 새로 만들고, 서버에는 처리본의 SHA-256 지문만 보낸다. 사진 업로드 API가 없다.
4. **본문을 저장·로그하지 않는다.** 서버 로그에는 건수·소요 시간만 남긴다.
5. 로그인·회원가입이 없고, 새로고침하면 브라우저 메모리의 데이터가 사라진다.

- **삭제·열람 요청 절차(처리방침 제7조):** 처리방침 화면의 "내 기기 ID"를 복사 → GitHub 이슈(공개 게시판이라 다른 개인정보는 적지 않도록 안내)에 기기 ID와 요청 내용을 적음 → 팀이 해당 ID의 `survey`·`intents` 행을 삭제(지문 기록은 지문 값으로 특정) → 10일 안에 처리하고 같은 이슈에 답글. 처리방침 화면은 ID를 **읽기만** 하고(처리방침을 본 것만으로 ID를 만들지 않음), 설문·의향 참여 때 만든다.

## 2. FR-01 기기 내 개인정보 제거 설계

정본 요구사항: 팀 PRD FR-01, 세부 명세: 팀 문서 08 「사용자 기기 개인정보 제거·전송 명세」. 핵심 원칙은 08과 같다. **원본은 브라우저 안에서만 읽고, 개인정보를 가린 별도 처리본을 만든 뒤, 사용자가 확인한 처리본(텍스트) 또는 그 지문(사진)만 서버로 보낸다.** 사용자 기기의 원본 파일을 지우거나 바꾸는 기능이 아니라 가린 사본을 새로 만드는 기능이다.

### 2-1. 흐름

**텍스트(공제 메시지)**

| 순서 | 어디서 | 하는 일 |
|---|---|---|
| 1 | 브라우저 | 원문 붙여넣기. 아직 아무것도 보내지 않음 |
| 2 | 브라우저 `mask.ts` | 주민등록번호·휴대전화·일반전화·계좌번호(하이픈 묶음)·이메일 패턴 + 사용자가 추가한 단어(이름·주소·호수)를 `[전화번호 삭제]`·`[이름 삭제]` 꼴로 치환 |

| 4 | 브라우저 | [이 전송본으로 정리하기]를 눌러야만 `POST /api/extract`로 처리본 전송. 원문을 고치면 확인이 풀리고, 치환에 실패하면 전송을 막음 |

### 2-2. 08 명세 대응표 (2026-10-03 기준, 정직하게)

판정: **구현** = 화면에서 동작 · **부분** = 일부만 또는 다른 방식 · **미구현** = 없음

| 08 요구 | 판정 | 실제 동작·차이 |
|---|---|---|

| 이름·상세 주소 탐지 | 부분 | **자동 탐지 없음.** 사용자가 단어(이름·주소·호수)를 추가하면 치환 |
| 로컬 OCR·로컬 탐지 모델로 사진 속 개인정보 후보 표시 | 미구현 | **로컬 OCR 없음.** 사진은 사용자가 직접 가림 상자를 그림(08 7절 "자동 탐지가 미구현이어도 직접 가리고 확인하는 경로" 해당) |
| 얼굴·서명·도장·QR 가림 | 부분 | 자동 탐지 없음, 수동 가림 상자로만 |
| 불투명 가림(블러·약한 모자이크 아님) | 구현 | 불투명 색으로 픽셀을 덮어씀 |
| 새 파일에 원본 레이어·썸네일 없음 | 구현 | canvas 재인코딩이라 단일 이미지만 남음 |
| EXIF·GPS·원본 파일명 제거 | 구현 | 재인코딩 + 결과 재검사. 파일명은 요청에 넣지 않음 |
| 전송할 파일을 다시 디코딩한 최종 미리보기 | 구현 | 사진 전송본 확인 단계 |
| 텍스트 치환 결과를 `[○○ 삭제]` 꼴로 보여 줌 | 구현 | 전송본 확인 패널 |
| 원문·가림이 바뀌면 확인 무효화 | 구현 | 텍스트는 원문 수정 시 확인 해제, 사진은 [다시 가리기] 시 처리본 재생성 |
| 치환·재인코딩·메타데이터 제거 실패 시 전송 차단 | 구현 | 실패하면 전송 버튼이 동작하지 않고 안내 |
| 미지원 형식 차단, 서버 변환 우회 없음 | 구현 | JPEG·PNG만. PDF·HEIC 서버 변환 없음 |
| PDF 페이지를 기기에서 이미지로 바꿔 가림 | 미구현 | 범위 밖(팀 PRD 10절) |
| 자르기·회전 후 좌표 일치 | 부분 | 긴 변이 너무 크면 줄이는 것만 있음. 자르기·회전 편집은 없음 |
| 원문·치환 대응표를 서버로 보내지 않음 | 구현 | 요청 본문은 처리본 하나 |
| 서버 보조 검사 | 구현 | `maskPII`가 입력·AI 응답을 다시 가림 |
| 서버에서 잔존 개인정보 의심 시 분석 보류·재편집 안내 | 부분 | 보류하지 않고 `●●●`로 다시 가린 뒤 진행 |
| 오류·분석 로그에 본문 없음 | 구현 | 건수·소요 시간만 |
| 원본을 브라우저 저장소·캐시·초안에 넣지 않음, 새로고침 시 자동 복원 없음 | 구현 | 메모리·object URL만, 새로고침하면 처음부터 |
| 세션 리플레이·분석 SDK가 원본을 보내지 않음 | 구현 | 그런 도구 자체를 쓰지 않음 |
| 처리본 **파일**을 서버로 보내 보관 | 해당 없음 | 사진 업로드 API가 없다. 서버는 처리본 지문만 받는다 |
| 변호사 상담 준비 파일(처리본 기준) | 미구현 | 07 7절의 상담 준비 메모는 범위 밖. 변호사 화면은 자료를 보내지 않음 |
| AI 기능만 AI로 표시, 패턴 치환·canvas 가림·조건 추천은 AI라고 하지 않음 | 구현 | AI 결과에만 "AI" 표시 |
| UI가 "모든 개인정보 완전 제거"라고 말하지 않음 | 구현 | 가린 항목 수와 처리본을 보여 주고 확인을 받는 방식으로만 설명 |

### 2-3. 이 설계로 말할 수 있는 것과 없는 것

| 말할 수 있음 | 말할 수 없음 |
|---|---|
| 원문·원본 사진은 정상 경로에서 서버로 가지 않는다 | 모든 개인정보를 자동으로 찾는다 |
| 서버로 가는 글은 사용자가 화면에서 확인한 처리본이다 | 이름·주소를 자동으로 가린다 |
| 사진 처리본에는 EXIF·GPS가 남지 않도록 다시 만들고 검사한다 | 사진 속 글자를 자동으로 읽어 가린다(로컬 OCR 없음) |
| 서버가 같은 패턴을 한 번 더 가린다 | 서버가 무단 요청·탐지 누락까지 막는다 |

## 3. FR-03 변호사 조건 추천의 법적 설계

정본: 팀 PRD FR-03, 세부 명세: 팀 문서 07 「변호사 추천·상담 연결 기능 명세」. 추천 규칙(꼭 필요/선호/상관없음, 가중치 주제 40·방식 20·지역 15·예산 15·시점 10, 미확인 0점 + "문의 필요", 동점은 확인일 최근 → ID 순)은 [PRD](PRD.md)에 있고, 여기서는 법적 위험과 대응만 적는다.

| 위험 | 근거 | 설계 대응 |
|---|---|---|
| 변호사 소개·알선의 대가 | **변호사법 제34조**: 법률 사건을 특정 변호사에게 소개·알선·유인하고 그 대가로 금품·이익을 받거나 약속하는 행위 금지 | 변호사에게서 **소개비·수수료·광고비를 받지 않는다.** 상담 연결 건수·수임 여부·상담료·회수액에 연동한 수익이 없다. 추천은 이용자에게 무료 |
| 돈으로 순위가 바뀌는 구조 | 제34조 취지, 이해상충 | 점수는 사용자가 고른 조건과 프로필의 확인 필드로만 계산한다. **순위 판매·유료 상단 노출 없음.** 기록북을 산 사람에게 더 높은 순위를 주는 구조도 없음 |
| 실존 변호사로 오인 | 표시·광고 오인 | 데모 프로필은 전부 **가상 프로필**이다. 화면 머리와 카드마다 "가상 프로필" 배지와 "실제 변호사가 아니며 연락·예약할 수 없어요" 안내 |
| 사건 정보 전달 | 개인정보 보호법 제17조(제3자 제공), 07 7절 | **연락·예약·자료 전송 기능이 없다.** 조건은 브라우저 안에서만 계산하고, 서버에는 익명 횟수만 간다. 가상 프로필에는 연락처·예약 URL·후기·승소 실적을 넣지 않는다 |
| 전문분야 표시 혼동 | 대한변협 전문분야 등록 제도(별도 심의) | 서비스 분류는 검색 태그일 뿐이다. 카드에서 **"주요 취급 업무"**와 **"등록 전문분야"**를 다른 칸으로 나눈다. 확인 안 된 "임대차 전문 변호사" 표현을 쓰지 않는다 |
| 실력·결과를 보장하는 듯한 표현 | 07 5-3, 과장·오인 | 라벨은 **"조건 일치 N"**으로만. "승소 가능성이 가장 높음", "이 사건에 최적", "반드시 선임해야 함", "회수액 보장"을 쓰지 않는다. 추천 이유는 확인 필드로 만든 고정 문장 |
| 정보가 없는 후보를 유리하게 | 07 5-2 | 미확인은 0점 + "문의 필요". 분모만 줄여 유리하게 만들지 않는다. 요금을 추측해 채우지 않고 "요금 문의 필요" |
| 조건을 몰래 완화해 결과 채우기 | 07 5-1 | 0명이면 "현재 조건으로 확인된 후보가 없습니다" + [조건 수정] + 대한변협 공식 변호사 검색 + 공공 무료 상담 경로 |
| 무료 공공 상담과 유료 변호사 섞기 | 07 1절 | 공공 무료 상담 기관은 점수에 넣지 않고 별도 안내(#/help) |
| 법률 판단 | 변호사법 제109조 | 상담 주제는 사용자가 고른다. AI가 책임 비율·승소 가능성·예상 반환액을 계산해 순위를 올리지 않는다 |

**실제 출시 전에 필요한 것 (지금은 하지 않음)**

| 항목 | 내용 |
|---|---|
| 실제 프로필 사용 조건 | 본인·사무실이 제공했거나 이용 조건을 확인한 공개 정보만. 공개 페이지가 있다는 사실을 자유로운 재사용 허가로 보지 않는다. 노출 동의·정정 요청 경로를 갖춘다 |
| 활동·등록 확인 | 대한변협 검색으로 실재·활동 상태 확인, 확인일 표시, 만료되면 재확인 전 노출 중지 |
| 광고 규정 검토 | 대한변협 변호사 광고 규정·온라인 플랫폼 관련 규정을 변호사와 검토. 광고를 넣는다면 표시 방식과 추천 순위를 분리 |
| 수익 구조 검토 | 프로필 노출·추천·수익 구조를 함께 법률 검토. 이 설계만으로 규제 적합성이 확정되지 않는다(07 8절) |

## 4. 법적 설계 원칙

보증금 지킴이는 **공개 자료를 정리해 보여 주는 정보 제공 도구**다. AI는 정리만 하고 판단하지 않는다. 판단과 발송은 사용자가 한다.

### 4-1. 위험과 대응

| 위험 | 근거 | 설계 대응 |
|---|---|---|
| 비변호사의 법률사무 취급 | **변호사법 제109조**: 변호사가 아니면서 금품·이익을 받거나 약속하고 법률 사건에 관해 감정·대리·문서 작성 등 법률사무를 취급하는 행위 금지 | 공제 책임·특약 효력·환급액·승소 가능성을 판단하지 않는다. 성공보수·해결 수수료를 받지 않는다. 유료 가설 상품은 방 사진 정리(기록북)와 빈칸 서식뿐 |
| 변호사 소개·알선 대가 | **변호사법 제34조** | 3절. 소개비·수수료·광고비 없음, 돈으로 순위 안 바뀜, 가상 프로필 명시, 연락·예약·자료 전송 없음 |
| 자동 문서 작성의 법률사무 해당 여부 | **로폼 사건**: 서울행정법원 2023구합60018 → 대법원 2025두35483 심리불속행 기각(2026-02-12). 이용자 입력이 그대로 반영되는 빈칸형 자동작성은 법률사무가 아니라는 취지. 생성형 AI가 문서를 작성하는 방식은 위반 소지가 언급됨 | 문의 문자·내용증명은 **고정 서식 + 사용자가 확인한 항목·금액만** 채운다. 이 단계에 **AI를 쓰지 않는다.** AI는 메시지에서 항목을 옮겨 적는 데만 쓴다 |
| 주민등록번호 처리 | **개인정보 보호법 제24조의2** | 어떤 입력란에도 주민등록번호를 받지 않는다. 붙여 넣은 글에 있으면 브라우저와 서버에서 가림 |
| 개인정보 국외 이전 | **개인정보 보호법 제28조의8** | OpenAI(미국)·Oracle(일본 도쿄 리전)을 처리방침 제5조에 고지(1-3). [AI 없이 직접 입력]으로 거부 경로 제공 |
| 생성형 AI 사용 고지 | **인공지능 기본법 제31조**(투명성) | 생성형 AI를 쓴다는 사실을 화면에 안내하고, AI가 만든 결과에 "AI" 표시 |
| 공갈 위험 | **형법 제350조**, **대법원 94도2422**(권리 행사라도 사회통념상 허용 범위를 넘는 해악 고지는 공갈이 될 수 있다는 취지) | 문의 문자는 근거를 묻는 문장만. 내용증명에 보증금과 관계없는 압박 문구(신고·폭로·인터넷 게시 등)를 넣으면 차단 |
| 과장·오인 표시 | 결과를 보장하는 듯한 문구는 이용자를 오인하게 할 수 있음 | 결론·과장 문구를 쓰지 않는다(4-2). 결제는 연결하지 않았다고 그대로 표시하고 결제 성공 화면을 흉내 내지 않는다 |
| 인증·공공기관 오인 | **정보통신망법 제47조·제76조**(5절) | 인증마크·정부 상징·기관 로고 미사용. 바닥글에 "학교 공식 서비스 아님", "인증 아님" 명시 |

### 4-2. 화면 문구 원칙

- **쓰지 않는 표현:** 공제가 부당하다는 결론, 판정, "돌려받을 수 있어요", "안 내도 됩니다", "기준과 다른", "AI 변호사", "법적 효력 보장", "승소", "전문 변호사"(확인 안 된 경우), "모든 개인정보 완전 제거".
- **쓰는 표현:** "확인 필요", "원문 확인 필요", "문의 필요", "요금 문의 필요", 참고 자료의 **범위 태그**("표준계약서 사용 시", "세입자에게 불리할 수 있음" 등), 출처 링크·확인일, "조건 일치", "가상 프로필".
- 세입자에게 불리할 수 있는 판결(91다22605)도 함께 보여 줘 한쪽 자료만 고르지 않는다.
- 상시 고지: "보증금 지킴이는 공개 자료를 찾아 보여 주는 정보 제공 도구이며, 법률 판단이나 대리를 하지 않습니다."

### 4-3. 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 공제 적정성·돌려받을 금액·승소 가능성 판단, 감가 계산 | 법률 판단(변호사법 제109조) |
| 성공보수·해결 수수료 | 이익을 받는 법률사무 취급 위험(제109조) |
| 변호사 소개비·광고비·순위 판매, 상담 예약 대행, 사건 자료 전달 | 소개·알선 대가 위험(제34조), 제3자 제공 |
| 문자·카톡 자동 발송, 내용증명 대리 발송 | 대리 행위 위험, 사용자가 직접 보낸다 |
| AI가 문의 문자·내용증명 문장 작성 | 로폼 사건에서 언급된 생성형 AI 문서 작성 위험 |
| 사진 촬영 시점 증명 | 서버 지문 기록은 "서버가 받은 시각"만 증명한다. 촬영 시점·법적 효력을 인증하지 않는다 |

## 5. 표시·마크 사용 근거

| 표시 | 쓰나 | 근거·이유 |
|---|---|---|
| 정보보호·개인정보 인증마크(ISMS·ISMS-P 등) | **쓰지 않음** | 받은 인증이 없다. 정보통신망법 제47조(정보보호 관리체계 인증)는 인증받지 않고 인증 표시를 하거나 인증 내용을 거짓으로 홍보하는 것을 막고, 위반 시 제76조에 따라 과태료 대상이 된다. 바닥글의 "준수·점검 표시"는 팀이 직접 지키고 점검한 사실을 적은 것이며 **인증이 아니라고 명시**한다. 도장·방패·원형 배지처럼 인증으로 보이는 모양도 쓰지 않는다 |
| 정부 상징·공공기관 로고(대법원·법무부·국민대 등) | **쓰지 않음** | 사용 권한이 없고, 공식 서비스로 오인하게 할 수 있다. 기관은 이름과 공식 홈페이지 링크로만 안내한다. 바닥글에 "학교 공식 서비스 아님" |
| 공공누리 제4유형 마크 | 씀(표준계약서 인용 카드에만) | 법무부 「주택임대차표준계약서」가 공공누리 제4유형(출처표시·상업적 이용금지·변경금지)으로 공개돼 있어, 원문을 **바꾸지 않고 인용**하며 출처와 마크를 표시한다. 인용은 무료 기능(공제 정리)에서만 보여 주고 유료 가설 상품에는 넣지 않는다. 유료화·상업적 이용 범위는 출시 전 재검토. 유형 설명: https://www.kogl.or.kr/info/licenseType4.do |
| 개인정보 처리 표시(라벨링) 아이콘 | 씀(처리방침 화면에만) | 개인정보보호위원회가 처리방침에 쓰도록 배포한 처리 표시(라벨링) 아이콘이다. 실제로 하는 처리에만 붙이고, 하지 않는 처리(제3자 제공)에는 붙이지 않는다. 인증이 아니라 처리 내용을 알기 쉽게 보여 주는 표시다 |
| 판결 요지 | 씀 | 판결 자체는 저작권 보호 대상이 아니다(저작권법 제7조). 요지는 팀이 판결문을 읽고 쓴 "취지"이며 출처 링크를 함께 둔다 |

## 6. 심사 질문 예상 답변

| 질문 | 답변 | 근거 문서 |
|---|---|---|
| AI가 법률 판단을 하나요? | 아니요. AI는 공제 메시지에서 항목명·청구액·원문 인용·확인 필요 여부만 옮겨 적습니다(구조화 출력, 판단 칸 없음). 인용이 원문에 없으면 서버가 "원문 확인 필요"로 바꿉니다. 공제 책임·특약 효력·환급액은 판단하지 않고, 사용자가 원문과 대조해 확인합니다. | 4-1, [PRD](PRD.md) FR-02 |
| 문의 문자·내용증명을 AI가 쓰나요? | 아니요. 둘 다 고정 서식이고, 사용자가 확인한 항목·금액만 들어갑니다. 발송도 사용자가 직접 합니다. | 4-1(로폼 사건) |
| 변호사 추천은 불법 아닌가요? | 변호사법 제34조는 소개·알선의 **대가**를 막습니다. 저희는 변호사에게서 소개비·수수료·광고비를 받지 않고, 돈으로 순위가 바뀌지 않으며, 연락·예약·자료 전송도 하지 않습니다. 지금 카드는 전부 가상 프로필이고 로직만 시연합니다. 실제 프로필을 쓰기 전에는 사용 조건과 광고 규정을 변호사와 검토합니다. | 3절 |
| 점수가 변호사 실력인가요? | 아니요. "조건 일치"는 사용자가 고른 주제·방식·지역·예산·시점과 프로필의 확인 필드가 얼마나 맞는지입니다. 07 명세의 가중치는 초기 설계 가설입니다. | 3절, [PRD](PRD.md) FR-03 |
| 개인정보가 해외로 가나요? | 네, 두 곳입니다. 공제 메시지 처리본은 OpenAI(미국)로, 서버 기록은 Oracle 도쿄 리전(일본)에 저장됩니다. 처리방침 제5조에 제28조의8 항목대로 고지했고, [AI 없이 직접 입력]으로 OpenAI 전송을 피할 수 있습니다. | 1-3 |
| 개인정보를 다 지워 주나요? | 다 지운다고 말하지 않습니다. 브라우저에서 번호·이메일 패턴과 사용자가 추가한 단어를 치환하고, 보낼 글을 직접 확인하게 합니다. 이름·주소 자동 탐지와 사진 로컬 OCR은 없습니다. 서버가 같은 패턴을 한 번 더 가립니다. | 2-2, 2-3 |
| 사진을 서버에 올리나요? | 아니요. 사진 업로드 API가 없습니다. 가린 처리본은 브라우저에서 만들고, 서버에는 처리본의 SHA-256 지문(64자)만 보냅니다. | 2-1 |
| 지문 기록이 촬영 시점을 증명하나요? | 아니요. "이 파일이 이 시각에 서버에 도착했다"는 기록(HMAC 서명·수신 시각)일 뿐, 촬영 시점이나 법적 효력을 증명하지 않습니다. 화면과 기록북에도 그렇게 적었습니다. | 4-3 |
| 공제 메시지를 저장하나요? | 아니요. 서버는 처리본을 OpenAI에 넘기고 응답한 뒤 버립니다. 로그에는 건수·소요 시간만 남습니다. OpenAI API 쪽은 정책상 최대 30일 보관될 수 있어 처리방침에 적었습니다. | 1-2, 1-3 |
| 인증마크나 기관 로고를 왜 안 쓰나요? | 받은 인증이 없고 사용 권한도 없기 때문입니다. 인증 없이 인증 표시를 하면 정보통신망법상 과태료 대상이 됩니다. 공공누리 마크와 개인정보 처리 표시 아이콘처럼 쓸 수 있는 것만 씁니다. | 5절 |
| 유료 상품은 어떻게 되나요? | 기록북 4,900원·내용증명 서식 2,900원은 **가격 가설**이고 결제는 연결하지 않았습니다. 구매 의향 버튼은 결제가 아니라 의향 기록입니다. | [PRD](PRD.md) 9절 |
