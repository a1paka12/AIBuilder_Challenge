## 3. 기능 목록

### 3-1. FR-01 기기 내 개인정보 제거·전송 (필수)

원칙: **원문과 원본 사진은 브라우저 안에서만 쓴다.** 서버로 가는 것은 사용자가 확인한 처리본 텍스트, 또는 처리본 사진의 지문(SHA-256) 64자뿐이다. 사진을 받는 서버 API는 없다.

#### 3-1-A. 텍스트 경로 상태 흐름 (SCR-02)

| 단계 | 화면 상태 | 사용자가 보는 것 | 다음 단계로 가는 조건 | 서버 전송 |
|---|---|---|---|---|
| 0 | 입력 | 공제 메시지 입력칸, 글자 수 "N / 3,000자", [정리하기] | [정리하기]를 누름 | 없음 |
| 1 | 개인정보 후보 확인 | "전송본 확인" 패널: 처리본(가린 자리를 강조), "가린 항목: [전화번호 삭제] 1 · [계좌번호 삭제] 1" | 자동 | 없음 |
| 2 | 가림 편집 | "가릴 단어 추가(이름·주소·호수 등)" — 종류 선택(이름 / 주소 / 기타) + 입력칸 + [추가], 가린 단어 칩(종류·단어)과 [×]. 추가한 단어는 `[이름 삭제]` · `[주소 삭제]` · `[가린 단어 삭제]`(기타)로 바뀜 | 단어를 넣거나 빼면 처리본이 바로 다시 만들어짐 | 없음 |
| 3 | 전송본 준비 | 갱신된 처리본과 가린 항목 수 | 처리본 생성 성공 | 없음 |
| 4 | 사용자 확인 | 확인란 "위 전송본을 확인했어요. 원문이나 가릴 단어를 바꾸면 다시 확인해야 해요." + [이 전송본으로 정리하기] · [원문 고치기]. 체크 전에는 "확인란을 체크해야 보낼 수 있어요."이고 버튼이 꺼져 있음 | 확인란 체크 → [이 전송본으로 정리하기]를 누름 | 없음 |
| 5 | 전송 중 | "정리하는 중…", 30초 넘으면 "AI 응답이 늦어지고 있어요. 조금만 기다려 주세요." | 서버 응답 | `POST /api/extract {text: 처리본}` |
| 6a | 완료 | "전송본 확인 완료 — 확인한 처리본만 서버로 보냈어요. 원문은 이 기기에서만 써요." + 정리 표 | — | — |
| 6b | 실패 | 오류 문구 + "붙여 넣은 글은 그대로 남아 있어요." + [다시 시도] · [직접 입력] | 사용자가 고름 | 재시도 때도 같은 처리본만 |

- 확인 무효화: 확인 뒤 원문이나 가릴 단어를 바꾸면 확인란이 풀리고 새 처리본으로 다시 확인해야 한다. [원문 고치기]는 패널을 닫고 입력칸으로 돌아간다(다시 [정리하기]를 눌러야 전송본 확인이 열림).
- 날짜(예: `2026-10-03`)와 숫자 10자리 미만 하이픈 묶음은 계좌번호로 보지 않고 남긴다.
- 치환 실패: 처리본을 만들지 못하면 전송을 막고 "개인정보 제거에 실패해 보내지 않았어요. 원문을 고친 뒤 다시 정리하기를 눌러 주세요."를 보인다.
- 국외 이전을 원하지 않는 사용자는 AI를 부르지 않고 직접 입력으로 시작할 수 있다(표만 직접 채움).

#### 3-1-B. 사진 경로 상태 흐름 (SCR-03, 가림 대화상자)

| 단계 | 화면 상태 | 사용자가 보는 것 | 다음 단계로 가는 조건 | 서버 전송 |
|---|---|---|---|---|
| 0 | 기기에서 읽는 중 | [사진 추가] 자리에 "사진 불러오는 중…" | JPEG·PNG이고 읽기 성공 | 없음 |
| 1 | 개인정보 후보 확인 | 대화상자 "1 / 2 · 개인정보 가리기", 원본 미리보기. 사진은 자동 탐지가 없어 사용자가 직접 살핀다 | 자동 | 없음 |
| 2 | 가림 편집 | 사진 위를 끌어 불투명 상자 그리기, [가림 상자 추가]·[넓게]·[좁게]·[높게]·[낮게]·[상자 삭제], 상자 목록 | [처리본 만들기]를 누름 | 없음 |
| 3 | 전송본 준비 | "처리본 만드는 중…" — canvas에 다시 그리고 상자를 #111 불투명 사각형으로 칠한 뒤 새 파일로 인코딩, 메타데이터 잔존 검사, 지문 계산 | 성공 | 없음 |
| 4 | 사용자 확인 | "2 / 2 · 전송본 확인", **처리본 파일을 다시 디코딩한 미리보기**, "메타데이터 제거됨", "개인정보 가림 N곳" 또는 "가린 곳 없음", "서버로 보내는 것: 이 처리본의 지문(SHA-256) 64자뿐이에요. 사진 자체는 보내지 않아요.", [지문 값 보기 (64자)] | [확인하고 기록하기] 또는 [다시 가리기] | 없음 |
| 5 | 전송 중 | 사진 카드에 "기록 남기는 중…" | 서버 응답 | `POST /api/receipt {sha256}` |
| 6a | 완료 | "서버 기록 · 2026-10-03 14:05 · 지문 1a2b3c4d" 배지 | — | — |
| 6b | 실패 | "서버 기록을 남기지 못했어요. (이유)" + [서버 기록 남기기]로 재시도 | 사용자가 누름 | 같은 처리본 지문만 |

- [다시 가리기]를 누르면 만든 처리본을 버리고 2단계로 돌아간다. 상자를 바꾸면 처리본을 새로 만들어야 확인할 수 있다.
- [취소]·[닫기]·Esc: 사진 추가 자체를 취소하고 "사진 추가를 취소했어요. 서버로 보낸 것은 없어요."를 알린다.
- 기록북·나란히 보기에는 처리본만 쓴다. 원본 파일명은 서버로 보내지 않는다.

#### 3-1-C. 기능 표

#### 3-3-B. 계산 규칙

```
1) 제외(후보 자격)
   - 선택한 주제 중 확인된 취급 업무가 하나도 없으면 제외
   - "꼭 필요" 조건(방식·지역·예산·시점·언어)을 충족하지 않으면 제외
   - "꼭 필요" 조건의 값이 프로필에서 확인되지 않으면 제외 (자동 통과 없음)

2) 활성 기준
   - 주제는 항상 활성
   - "상관없음"인 기준은 모든 후보에서 똑같이 뺀다
   - 지역은 방문을 골랐고 방식·지역이 "상관없음"이 아닐 때만 활성(전화·영상만 고르면 뺀다)
   - 정보가 없는 후보만 분모를 줄이지 않는다 (미확인 = 0점 + "문의 필요")

3) 조건 일치 점수
   점수 = round(100 × Σ(활성 기준 가중치 × 일치값) ÷ Σ(활성 기준 가중치))

4) 정렬
   점수 높은 순 → 동점이면 프로필 확인일 최근 순 → 고유 ID 순
   (상담료·광고·수수료는 순위에 쓰지 않는다)

5) 표시
   상위 최대 3명 + [전체 후보 보기 (N명)] / [상위 3명만 보기]
   0명이면 가장 많이 거른 꼭 필요 조건(그중 정보 미확인 수)을 알려 줄 뿐, 조건은 바꾸지 않는다
```

**검산 예시(07 명세 5-4 = 화면의 [예시 조건으로 보기]: 주제 원상회복 비용·보증금 반환 · 방문 · 서울 동북권 · 5만원 이하 · 3일 이내, 모든 기준 "선호", 언어 상관없음)** — 주제가 겹치는 후보 6명(F·H 제외) 중 A·B·C가 먼저 나온다.

| 가상 후보 | 주제(40) | 방식(20) | 지역(15) | 예산(15) | 시점(10) | 조건 일치 |
|---|---:|---:|---:|---:|---:|---:|
| A | 40 | 20 | 15 | 15 | 10 | 100 |
| B | 40 | 20 | 0 | 15 | 0 | 75 |
| C | 20 (주제 2개 중 1개) | 20 | 15 | 0 | 10 | 65 |

- 예산을 "꼭 필요"로 바꾸면 예산을 넘는 C(30분 8만원), 요금 미확인 D·G, 20분 요금이라 비교할 수 없는 E가 빠져 A·B만 남는다.
- 방식을 전화만 고르면 지역 15점을 모든 후보의 분자·분모에서 빼고 다시 계산해 A 100 · B 88 · C 59가 된다.
- 동점이면 확인일 최근 순 → ID 순. 위 검산은 `node scripts/lawyer-check.mjs`가 자동으로 확인한다.

## 4. 역할 분담

**패턴 치환·Canvas 가림·결정적 추천(변호사 조건 일치 점수)은 생성형 AI 기능이 아니다.** 생성형 AI를 쓰는 곳은 공제 문자 항목 추출 한 곳뿐이며, 그 결과에만 "AI" 배지를 붙인다.

| 영역 | AI가 하는 일 | 코드 규칙이 하는 일 | 사람이 하는 일 |
|---|---|---|---|
| 개인정보 제거(텍스트) | 없음 | 숫자·이메일 패턴 치환, 사용자 단어 치환, 전송본 표시, 확인 전 전송 차단, 서버 2차 가림 | 가릴 단어 추가, 전송본 확인 |
| 개인정보 제거(사진) | 없음 | JPEG·PNG 확인, 불투명 칠하기, canvas 재인코딩, 메타데이터 잔존 검사, SHA-256 계산 | 가릴 영역 판단·상자 그리기, 처리본 확인 |
| 공제 정리 | 항목명·청구액·원문 인용·확인 필요 여부를 옮겨 적기 | JSON Schema 강제, 금액 범위·인용 존재 검사, 개인정보 재가림, 합계 계산 | 원문 대조, 수정, 확인, 물어볼 항목 선택 |
| 참고 자료·특약 | 없음 | 고정 자료 5종 표시, 특약 키워드 대조 | 자료 읽기, 특약 붙여넣기 |
| 문의 문자·내용증명 | 없음(작성하지 않음) | 고정 서식에 확인값만 넣기, 압박 문구 차단 | 보낼지 결정, 직접 발송 |
| 변호사 찾아보기 | 없음 | 제외 규칙, 조건 일치 점수, 정렬, 추천 이유 고정 문장 | 주제·조건·중요도 선택, 상담 여부·연락 결정 |
| 판단 | **하지 않음**: 공제 책임, 특약 효력, 환급액, 적정 수리비 | 결론 문구를 만들지 않음 | 모든 판단은 사용자(필요하면 상담 기관·변호사) |
