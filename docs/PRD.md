# 보증금 지킴이 PRD

팀명: MOTGA | 작성일: 2026-10-03

## 1. 한 줄 소개

자취생이 보증금 공제 내역과 입주·퇴실 자료를 AI로 정리하고, 문의할 내용과 상담 조건에 맞는 변호사를 찾는 AI 주거 기록 서비스.

## 2. 문제 정의

- 사용자가 지금 겪는 불편: 퇴실 시 청소·도배·장판 비용을 통보받으면 공제 항목과 금액을 옮겨 적고, 사진·계약 내용을 찾아 첫 문의를 작성해야 한다. 상담이 필요하면 변호사의 업무 분야·지역·방식·비용도 직접 비교해야 한다.
- 이 문제가 중요한 이유(근거, 숫자, 경험): 사례 조사에서 입주 사진 부재, 특약 확인, 견적·영수증 부족, 상담 준비가 반복적인 쟁점으로 나타났다. 개인정보가 담긴 자료를 외부 AI에 그대로 전달하는 부담도 있다. 초기에는 공제 항목 5개 확인부터 문의 복사까지 중앙값 3분 이내를 목표로 검증하며, 현재 시간 절감 효과와 구매 수요는 미검증이다.

## 3. 타깃 사용자

- 주요 사용자: 전국 대학가의 원룸·오피스텔 등에 거주하는 자취생. 입주·퇴실을 앞두었거나 공제 내역을 받은 학생, 일반 임차인 전체를 우선 대상으로 한다.
- 언제, 어디서 쓰나요: 공제 메시지를 받은 직후, 입주·퇴실 사진을 정리할 때, 상담을 준비할 때 휴대전화 또는 데스크톱 웹에서 사용한다. 입주 사진이나 계약서가 없어도 공제 메시지만으로 정리·문의 기능을 이용한다.

## 4. 해결 방법과 차별점

- 핵심 아이디어: 사용자 기기에서 개인정보를 제거한 뒤 AI가 공제 항목·금액·근거 문장을 추출하고, 사용자가 확인한 항목으로 문의를 준비한다. 상담 조건에 맞는 변호사를 추천하고 입주·퇴실 사진은 기록북으로 정리한다.
- 기존 서비스와 다른 점: 한국어 공제 정리, 기기 내 개인정보 제거, 원문과 금액 확인, 추천 이유가 보이는 변호사 탐색을 연결한다. AI는 공제 책임·특약 효력·환급액을 판단하지 않으며, 문의는 사용자 확인값을 넣는 고정 템플릿으로 제공한다.

### 5-1. 필수 기능의 세부 동작 (채점 대조용)

**FR-01 기기 내 개인정보 제거·전송**

| 구분 | 동작 |
| --- | --- |
| 텍스트 자동 탐지 | 브라우저(`src/lib/mask.ts`)에서 주민등록번호·휴대전화·일반전화·계좌·이메일 패턴을 찾아 `[전화번호 삭제]` 형식으로 치환. 이름·주소·호수는 사용자가 단어를 추가하면 `[이름 삭제]` 형식으로 치환 |
| 전송본 확인 | "전송본 확인" 패널에 실제 처리본과 가린 항목 수를 표시. [이 전송본으로 정리하기]를 눌러야만 처리본이 `/api/extract`로 전송. 원문을 고치면 확인이 해제되고, 치환에 실패하면 전송이 막힘 |
| 서버로 가는 것 | 처리본 파일. 원문과 치환 대응표는 서버로 가지 않음. 서버(`server.mjs` maskPII)가 2차로 다시 가리고 AI 응답도 재검사 |
| 사진 형식 | JPEG·PNG만 받음. 그 외 형식은 차단하고 안내 |
| 사진 가림 | 사진 위에 불투명 가림 상자를 포인터 드래그 또는 키보드로 추가·이동·크기 조절 → canvas 재인코딩으로 새 파일 생성(EXIF·GPS 등 메타데이터 제거) |
| 사진 전송본 확인 | 가린 처리본을 다시 연 미리보기로 "전송본 확인" → [확인하고 기록하기] → 로그인한 경우 가린 처리본 사진을 내 계정에 저장(처음 한 번 [필수] 보관 동의, 원본·메타데이터 미전송), 로그인하지 않으면 처리본의 암호화 해시값(SHA-256)만 `/api/receipt`로 기록. 원본 파일명은 보내지 않음. 기록북에는 처리본만 쓰임[^upload] |

## 6. 사용자 흐름

1. 사용자가 첫 화면에서 공제 정리·기록북·변호사 찾기 또는 합성 예시 체험을 선택하고, 자료를 입력하는 경우 기기 내 개인정보 제거와 전송본 확인을 완료한다.
2. AI가 정리한 항목·금액을 원문과 대조해 수정·확인하고 물어볼 항목을 선택한 뒤 공개 자료와 합계를 확인하고 문의 문구를 복사한다.
3. 상담이 필요하면 조건에 맞는 변호사 후보나 공공 상담 경로를 선택하고, 사진 기록을 남기려면 별도로 기록북을 편집해 PDF로 저장한다.
4. 첫 방문 시 레이어 팝업(출시 이벤트·혼자 묻기 어렵다면)을 보고 닫거나 #/event·#/help로 이동할 수 있고, 다음 단계에서 #/cert 내용증명 빈칸 서식을 채워 PDF로 저장할 수 있다. 30초 현장 설문(회원가입 마지막 단계·#/event)과 #/pricing 구매 의향은 결제 없이 응답만 기록한다.[^survey]

  - 잠재고객: 전·월세 등 주택 임대차 계약을 맺고 퇴실 과정에서 보증금 공제 문제를 경험할 수 있는 일반 임차인 전체를 잠재고객으로 정의한다. 대학생, 사회초년생, 직장인, 1인 가구, 신혼부부 등 임대차 경험은 있지만 원상복구 및 보증금 공제 대응에 익숙하지 않은 사용자가 주요 대상이다.
  - 계약고객: 무료 체험 이후 실제 공제 대응, 입주 기록, 내용증명 서식 등 유료 기능에 필요성을 느낀 사용자를 유료 계약고객으로 전환한다. 결제 전환율과 환불률을 통해 실제 지불 의사를 검증한다.
- 경쟁 서비스와 우리 강점: 범용 AI, 수동 사진 정리, 공공 상담이 대체 수단이며 입주·퇴실 기록과 보고서 공유를 제공한다. MOTGA는 한국어 공제 정리, 사용자 기기 내 개인정보 제거, 원문 확인, 상담 조건별 변호사 탐색을 연결하는 경험에 집중한다.

## 10. 이번에 만들지 않는 것 (범위 밖)

- 장기 보관[^photo]·실결제·기관 대시보드[^signup], 이미지 공제 내용 자동 추출·전체 계약서 분석·로컬 OCR 자동 가림, 공제 책임·환급액·적정 수리비 판단, 사진 촬영 시점·법적 효력 인증, AI 법률문서 작성·자동 발송, 변호사 예약 확정·자료 자동 전달·유료 추천 순위, 원본 서버 보관[^photo]·공개 공유 링크.

## 각주

[^date]: 화면에 날짜 입력칸이 없고, 서버가 사진을 기록한 시각이 "기록 날짜"로 자동 표시된다(사진 속 촬영 정보는 지워서 쓰지 않음).

[^nav]: 팀 원문의 '상단 메뉴'가 헤더 아래 업무 바로가기 아이콘 줄(공제 · 기록 · 변호사 · 상담 · 내용증명 · 이벤트 · 가격 · 고객센터)로 바뀌어 실제 버튼 이름에 맞췄다. 바닥글에는 업무 메뉴를 두지 않는다.

[^survey]: 30초 설문은 첫 화면이 아니라 회원가입 마지막 단계(건너뛰기 가능)와 #/event에 있고, #/pricing은 사람 수가 아니라 상품별 의향 건수를 보여 준다.

[^popup]: 팀 원문의 '레이어 팝업 2칸'은 두 칸이 한 번에 보이는 모양이지만, 화면은 안내를 한 장씩 보여 주고 [이전 안내]/[다음 안내]로 넘긴다(1 / 2 표시). 닫는 방법과 이동 버튼은 같다.

[^privacy]: FR-10(회원가입·사진 보관)이 생겨 처리방침에 회원 정보·저장 사진·로그인 쿠키·만 14세 미만 조항이 반영되었고, 바닥글은 사업자 정보 안에 고객센터(온라인 문의)와 [개인정보 처리방침 보기] 링크를 두는 구조로 바뀌었다.

[^upload]: 로그인 사용자의 가린 사진 보관(FR-10, `/api/photos`)이 생겨 '사진 업로드 API는 없음'이 더 이상 사실이 아니다. 로그인하지 않으면 예전처럼 해시값만 보낸다.

[^score]: 코드(`src/lib/lawyerMatch.ts`)는 점수를 반올림한 정수로 보여 주고, 방문 미선택·방식 상관없음·지역 상관없음 중 하나면 지역을 계산에서 뺀다.

[^lw]: 변호사 화면이 폼과 결과를 한 화면에 두던 방식에서 '조건 고르기 → 후보 보기' 단계식으로 바뀌었다.

[^home]: 업무 바로가기는 헤더 아래 아이콘 줄로, 업무별 상세는 #/support로, 30초 설문은 회원가입·#/event로 옮겨 첫 화면 순서가 바뀌었다. 서비스 원칙 마크는 첫 화면 본문에 두지 않고 바닥글에만 둔다.

[^server]: FR-10 회원가입·사진 보관으로 인증·사진 API와 테이블 2개(users·photos), 사진 파일 폴더가 늘었다. '사진은 저장하지 않음'은 원본 사진 기준으로만 맞다.

[^ad]: 팀 원문 '변호사 소개 광고비를 청구한다'를 변호사법 제34조와 07 명세 8절(광고비를 추천 점수에 반영하지 않음)에 맞게 다듬음.

[^photo]: '장기 보관'과 '원본 서버 보관'은 범위 밖 그대로다. 원본은 보관하지 않고, 로그인 회원이 동의하고 저장한 가린 처리본만 본인 계정에 최대 2026-12-31까지 둔다(삭제·탈퇴 즉시 삭제, 공개 링크 없음). 영구 보관이 아니다.

[^signup]: 팀 원문에는 '회원가입'이 범위 밖으로 적혀 있었으나, 사용자 결정(10/3)으로 회원가입·구글 간편 가입을 FR-10으로 구현해 범위 밖에서 뺐다.
